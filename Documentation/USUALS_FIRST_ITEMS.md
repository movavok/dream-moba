# USUALS tier-I items: editor setup and play checks

## Configuration

The three `ItemDefinition` assets are `Assets/Scripts/Items/RottenTomato.asset`, `Soap.asset`, and `Pillow.asset`. They are listed in `ItemDatabase.asset` and the existing `UsualsCatalog.asset` at Attack I/2, Survival I/2, and Survival I/1 respectively. All three initial prices are 50, editable in the catalog. The matching world prefabs are registered in `DefaultNetworkPrefabs.asset`. The inventory and Buy preview read their respective item/world sprites from these assets. Check their import and GameScene network registration in Unity.

**Tomato:** `RottenTomatoWorld.prefab` contains `WorldItem`, the existing `ItemThrowMotion`, and `RottenTomatoImpact`. Configure damage, splash/flight radii and hitbox layers there. Strong-throw multiplier 3 is on `RottenTomato.asset`. The wall sweep is the existing `ItemThrowMotion` collision logic; its mask on this prefab excludes character bodies/hitboxes/projectiles but includes map obstacles. `TomatoBlind.asset` sets the **2.5-second** debuff and character overlay. Its **Screen Overlay** is `tomato-screen.png`: one full-screen Image at original sprite colors/alpha, with 0.1s fade-in and 0.18s fade-out within the 2.5s status; there are no duplicate spots or input-blocking raycasters. Health on Player/Boar/Scarecrow/TrainingDummy registers this status definition. Once the user authors a Head Point Transform under each actor, assign it to that prefab's **Health > Status Head Point**: the tomato overlay is instantiated at that Transform's origin and follows it. Until assigned, the old **World Offset** on TomatoBlind plus **Status Visual Offset** on Health remain the fallback. Direct hit and expanding splash share one per-thrown-item hit set, and teammates are filtered through Team.IsEnemyFor.

### Finish connecting the existing tomato burst in Unity

1. Your `Assets/Animations/UI/tomatoBurst.anim` (nonlooping, **0.5 s**) and `TomatoBurst.controller` are already connected to `Assets/Prefabs/Effects/TomatoBurst.prefab`; that prefab is already assigned to `RottenTomatoWorld.prefab > RottenTomatoImpact > Animated Splash Prefab`. **Splash Duration** is set to **0.5 s** to match the clip. No separate network prefab registration is needed for this local animation.
2. In `Assets/Sprites/UI/tomato-burst.png` > **Sprite Editor**, slice the *full frames* in playback order (for the current 128×32 image, four 32×32 cells left to right). Use the same canvas size and **centered pivot** for every frame so the splash does not jump. Its current automatic nine-sprite slicing extracts fragments from the fourth frame. Keep the four existing clip frame references (`tomato-burst_0` through `_3`) intact or reassign them in the Animation window after slicing; the original importer configuration was not changed here.
3. Preview the prefab's SpriteRenderer and Animator: first frame should be the assigned Sprite, the controller's default state should play `tomatoBurst` once. The clip currently includes constant SpriteRenderer **Size X/Y** curves in addition to Sprite keys; these do not change the Transform scale in Simple draw mode, but you can remove them in the Animation window to keep the clip Sprite-only. Do **not** animate Transform scale or position: `ExpandingSplashVisual` owns those. If you later change the clip's length, set **Splash Duration** to the new value. The old **Splash Prefab** particles are a fallback only when Animated Splash Prefab is unassigned.
4. On `TomatoBurst.prefab` there are four **Frame 0/1/2/3 Hit Shape** children with individual *disabled*, *trigger* `CircleCollider2D` components and a `SplashFrameColliders` list at the root binding each clip Sprite to its matching collider. Enable a child collider temporarily in Prefab Mode to edit its green outline, adjust **Radius** and **Offset** for that frame, then disable it again. You can replace any circle with BoxCollider2D/PolygonCollider2D; update that frame's **Collider** reference in `SplashFrameColliders`, keep **Is Trigger** on. No Animation Events or collider-enable keys are needed: server playback selects the shape whose **Sprite** matches the Animator's currently displayed sprite and queries overlaps on every server step. Client visuals keep the gameplay colliders off. When you re-slice the sprite sheet, check that all four Sprite references in the clip **and** `SplashFrameColliders` still point to the intended frames; missing mappings warn once and do not deal splash damage for that frame.
5. **Splash Radius** on RottenTomatoWorld > RottenTomatoImpact sets the final visual radius in world units and scales all four collider shapes with the animation; **Splash Duration** still controls the lifetime. With equally sized 32px frames imported at 100 pixels/unit, each full frame is 0.32 world units wide. At radius **0.65**, visual final diameter is **1.3** units, so a last-frame local `CircleCollider2D.Radius = 0.16` becomes **0.65 world units** after the final scale multiplier 1.3/0.32. Earlier colliders can grow with the artwork (starter radii 0.08/0.105/0.13/0.16). Changing Splash Radius scales all frames proportionally; individual collider size/offset and even shape remain editable in the prefab. If you change frame import PPU or visual bounds, retune the authored collider shapes. The tomato prefab's selected radius gizmo remains a guide; the per-frame colliders are authoritative when configured, with circle sampling as fallback only when no frame-collider bindings exist.

Repeated tomato hits refresh the existing screen overlay until the latest server end time; cleansing fades it out early. Gameplay uses the same status duration on heroes and boars.

**Soap:** `SoapUse.asset` owns the three-second immunity duration; `Soap.asset` uses that existing ItemUseAction path. `Health` owns the actual cleanse, immunity deadline and burn removal; `StatusDefinition` marks negative/cleansable/immunity-bypassing effects individually. `TomatoBlind` and `MushroomSlow` are registered on Player Health. Future debuffs should be authored as `StatusDefinition` assets and assigned to Health, rather than inferred from negative stat modifiers. The existing `SlowAura` now requests its configured status instead of adding its own independent stat modifier; assign `MushroomSlow.asset` to its **Slow Status** when authoring a mushroom aura. Configure its duration longer than its scan interval. Stun should be authored with **Cleansable** off and **Bypass Immunity** on. Existing flag carrying remains unaffected.

The player `HeroEffectVisuals` binding now points to `SoapUse.asset` and the **existing** `bublesParticles.prefab`, instead of EnergyDrinkUse. `Health` turns that binding on while its single immunity deadline is live, and turns emission off on expiry/death; HeroEffectVisuals allows emitted particles to finish naturally. EnergyDrinkUse's speed bonus and duration are untouched.

**Pillow:** `Pillow.asset` configures max charges 2 and basic-attack blocking. Charges are serialized per `InventorySlot`, not on the shared ItemDefinition. Inventory, container transfer, world item pickup/throw and death drop carry this state. Inventory and container HUD read the same value to display the vertical bottom-up filled icon and the `(2)`/`(1)` title. `ProjectileNetwork` marks its own hit as a basic attack and asks Health/selected Inventory for a block **before** damage feedback, damage, on-hit sounds and streak. **Is Basic Attack** is explicitly enabled on `Projectile-kuroshi-baseAtk.prefab` and the shared `Projectile.prefab`; set it off on future non-basic projectiles. `ItemPopupVisual.prefab`, referenced from Player Health via **Block Popup Prefab**, draws the Pillow WorldItem sprite only on a successful block. Its Inspector exposes duration, growth, rise, sideways shake, sway cycles and angle; no physical item is spawned by blocking. If the 0 appears but no pillow is visible, check the Player Health prefab reference, PillowWorld's Visual SpriteRenderer.Sprite and the popup SpriteRenderer sorting layer/order.
