# Lighter, banana peel and Stun

## Where to configure

- `Assets/Scripts/Items/Lighter.asset`: **Max Charges** = 5, **Max Stack** = 10 and **Ignites Basic Attacks** enabled. Select the lighter slot and make a basic attack to spend one charge of the current lighter; no Space activation. When its fifth charge is spent, that unit is removed and the next full lighter in the stack becomes current. `Assets/Scripts/Items/LighterAttackConfig.asset` holds **Attack Fire Prefab**; both basic-attack projectile prefabs reference this same config via **Lighter Settings**. Its current ParticleSystem reference is retained and can be reassigned in the Inspector. Each projectile holds a server-owned ignition bit from launch until despawn; each observer spawns particles only as a child of that projectile, not on the attacking hero. Impact uses the existing `Health.Ignite()` burning implementation, **not a StatusDefinition asset**: the project has no burn StatusDefinition to assign, and the existing burn tick, spread and visual continue to be the source of truth.
- `Assets/Prefabs/BananaPeelWorld.prefab` > **BananaPeelTrap**: **Stun Duration** (1 s), **Trap Collider** (StepTrigger child), **Body Layers** (PlayerBody, layer 6), **Stun Status** (`Stun.asset`). The separate root circle remains the world-item interaction shape. Banana has no Space use; normal/strong inventory throws use the existing ItemThrowMotion. Once thrown, the peel cannot be picked up again, including after landing; naturally spawned shop/world items remain collectible and unarmed until thrown. The peel's throw obstacle mask excludes PlayerBody so a throw can land under an existing creature instead of being pushed away. A grounded trap queries actual overlapping non-trigger body colliders each physics step, including on the first step after landing. It is inert while `WorldItem.IsFlying` and despawns once a valid status application succeeds. Either team and the owner are eligible.
- `Assets/Scripts/Items/Stun.asset`: **Duration** 1 s, **Blocks Actions**, negative, bypasses soap immunity and is not cleansable (as already stated in the soap description). **World Effect Prefab** currently references `Assets/Prefabs/Effects/stunPart.prefab`. Clients attach a zero-offset anchor to the affected Health's **Status Head Point** and instantiate the VFX inside it with the prefab's own local offset retained (currently Y = 0.6). Set any desired visual offset in that prefab. `stunPart` now uses a short particle lifetime, continuous emission and local simulation so it remains visible during the 1-second stun and follows the actor. Player, Boar, Scarecrow and TrainingDummy Health already register the same Stun asset and have HeadPoint bindings; new creature prefabs must register it and provide a HeadPoint to respond/attach VFX. Status end, death and despawn clean up the local VFX.
- `Assets/Scripts/Items/UsualsCatalog.asset`: Lighter in Attack I/1 and Banana Peel in Mobility & Control I/2, each initially 50 gold; item entries are in `ItemDatabase.asset`. Both world prefabs are in `DefaultNetworkPrefabs.asset`.

## Authority

All inventory use/throw, projectile ignition consumption, hit/burn and banana overlap/stun/despawn happen on the server. Movement, attack, abilities, item use/throw, world interaction, container transfer, shopping and carried-flag delivery have server-side stun gates; boar AI/charge and scarecrow reflection are suppressed while stunned. Ability timers, normal cooldowns, existing burn, damage and other independent statuses continue. Blocking queries use currently active statuses rather than toggling components so expiry does not undo unrelated restrictions.

Charged items now stack up to their authored Max Stack (Pillow also has 10). A slot stores the **current** item's charge count, with any remaining items in that stack fully charged. A partially used unit can merge into a full stack, but two partially used units stay in separate slots rather than losing charge information. Throwing or transferring one takes the current unit; when it is spent or removed, the next full unit becomes current. Death drops retain the current unit's charge count and give the other dropped units their full charges.

## Unity checks for the user

Import/compile the new prefabs, assets and scripts. Check or replace the current fire ParticleSystem reference in LighterAttackConfig and (when authored) assign stun VFX on Stun. Verify selected lighter launches exactly five igniting basics including misses, deselect/reselect and abilities, no Space use, and that the last launched projectile still ignites after the charge reaches zero. Check 2+ pillows and lighters stacked in one slot, current-unit charges, partial/full merging, one/whole transfers, throws, death drops and respawn. Verify banana throw, no airborne stun or post-throw pickup, overlap on landing, body-vs-hitbox distance, owner/ally/enemy/boar/scarecrow/dummy, one consumption, stun during boar charge and scarecrow reflection, soap coexistence, death/respawn, and host/client/late join cosmetics.
