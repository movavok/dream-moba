# Team visibility and minimap — agreed design

Recorded: 2026-11-14. The user supplied a Minimap Image in GameScene and confirmed the static Grid capture and corrected player dots/frames look good. Detection of enemies and objectives is now in source but awaits Play Mode verification.

## Agreed gameplay rules

- Outside buildings, each player contributes the **actual visible rectangle of their own output camera**. The team's visible region is the union of all its outside rectangles. This includes dead players' spectating cameras (their actual view, rather than an extra radius around their corpse); when the spectated camera is inside a building, its outline/vision is hidden too. The local rectangle has a yellow outline on the minimap; teammates' rectangles have white outlines.
- Camera view sizes can differ with resolution/window aspect ratio. The game camera is currently orthographic (size 5, roughly 10 world units high), with Cinemachine follow damping and house/map confinement. Determine each rectangle from the rendered camera's four viewport corners projected onto the 2D world plane, **not** a fixed radius or an assumed 16:9 viewport. Recompute after resize, camera cut, house transition and spectator switch. Clip outlines to the map bounds.
- An object inside any contributing teammate's view is known to the whole team: enemy heroes, creeps, minibosses, flags and dropped items, with an extensible category/marker definition for later objects. There is currently no behind-wall hiding rule outside buildings. Local player and teammates have team-color dots; on entering a building, their dot freezes at the last outside position, becomes square, and their camera outline disappears. On exiting, the dot resumes following and becomes round. An initial spawn inside without a prior exterior position uses the spawn position as fallback. Once an enemy/object leaves every contributing view, its marker disappears immediately; no last-known position.
- Buildings and other static geography belong on the map background rather than dynamic visibility markers. Dynamic objects are not permanently marked, even objectives; flag, scarecrow and loose items appear only while in a team's views. Disappearance, despawn, team changes, drops and respawns update the markers without stale entries.
- Off-screen arrow scripts now reuse the same team-visible enemy check; allies are always eligible. An arrow appears only when the target sprite is completely outside *my* current viewport, uses its team color, and fades in/out without updating a no-longer-visible enemy's position. The separate local flag-delivery pointer shows near the carrier's feet only while the flag is carried and selected in inventory; it points to the active delivery zone. The user supplied and assigned both arrow sprites and reports the visuals work; wider host/client verification remains. Extending edge arrows to objectives is a later option.

## Architecture and implementation order

1. **Map coordinates/background.** First source slice now captures all active renderers beneath the GameScene Grid once on scene load, cropped to the scene's main CameraBounds, at point-filtered 256-pixel resolution, into the user-supplied Minimap Image. It includes Tilemaps, large building sprites and new Grid children added only in GameScene; MapScene has only the base Grid prefab and misses those local additions. The previous generated placeholder UI/player pixel/outline was removed at the user's request. Verify rendering order, bounds, quality and that unwanted interiors do not appear; if they do, classify/exclude those renderers explicitly in the next step. Dynamic/network entities outside Grid and gameplay UI are excluded. Re-entering the scene re-captures map edits; no manual repaint.
2. **Shared visibility feed.** `TeamCameraViews.IsVisible` now checks the intersection of the target sprite's world bounds with the union of the local camera rectangle and recent teammate rectangles; cameras inside buildings do not contribute. The server relays each camera rectangle only to teammates, including spectators. This is UI-level spotting: transforms of spawned enemy objects are still replicated globally. If hidden network data becomes a requirement, add server-side observer filtering and validation separately.
3. **Minimap UI.** `MinimapTeamOverlay` now draws 14-pixel local/allied team-color dots, visible enemy team-color dots and outside camera rectangles on the user's map Image. `MinimapObjectMarkers` uses the same visibility check: ordinary WorldItems use yellow dots, a grounded/thrown flag uses a large yellow triangle, a carried flag follows its carrier and takes the carrier team's color (enemy carrier only when spotted), and a living scarecrow miniboss uses an orange cross. Both overlay components reuse the same CameraBounds projection. Test Play Mode with late join, different screen aspect ratios, spectator switching, outside/inside transitions, item pickup/throw, flag carry/drop, boss death/respawn and marker edge clipping. Extend entity categories via reusable registration if more types are added.
4. **Edge arrows.** `OffscreenPlayerArrows` is wired on the GameScene Canvas with configurable sprite, UI container, size, margin, opacity, fade, follow smoothing and rotation offset; the user's edge-arrow sprite faces **upper left** by default (offset -135 degrees). `FlagDeliveryDirection` uses a separate upward-facing sprite (offset -90 degrees) and a world SpriteRenderer that switches behind the hero when pointing up; radius, scale, offset, sprite and sorting layers are configurable. Both sprites are assigned in GameScene; the user reports the arrows work. Verify live Arrow Size edits, team colors, selection/carry/drop, building fade, multiple targets and different resolutions on host/client.
5. **2v2 verification.** Compare host/client lists when views overlap and separate; test different resolutions and window resize, house cuts, deaths/spectating, fog-free building interiors, boss respawn, flag carry/drop, item pickup/drop, and late join. Check marker correctness under packet delay and packet loss.

## Important distinction

The current network prefabs broadcast transforms to clients, including out-of-view players. Team visibility as described initially controls **game UI and shared spotting**, not network secrecy or hiding already-rendered world objects. If competitive information hiding is needed later, server-side network interest/observer filtering and visibility-aware gameplay logic must be designed as a separate layer; never treat the client-side minimap filter alone as an anti-cheat boundary.
