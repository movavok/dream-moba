# Dream MOBA project progress

1. Read `Documentation/PROJECT_PROGRESS.md` and, when needed, `README.md` and relevant source or git history before answering. Distinguish documented prototype features from independently verified functionality.
2. For a progress report, summarize completed/documented work, current focus, blockers or uncertainty, and concrete next steps. Do not interpret a modified file as a finished feature.
3. When asked to save progress, or after finishing substantial work, update `Documentation/PROJECT_PROGRESS.md`: date the entry, describe what changed, link to relevant paths, note verification (or that it was not run), and keep the next steps actionable. Keep established context unless evidence supersedes it; avoid recording speculative claims as facts.
4. This file is persistent project memory, not a transcript of chats. Never store secrets or large generated logs there.
